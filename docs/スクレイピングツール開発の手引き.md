# 公開サイトからExcelを作るツール ― 着手手順

次に似たツールを作るときに**最初に読む**もの。
実例・実装の詳細は `kaigo_kensaku/README.md` にある。ここは手順だけ。

前回（`kaigo_kensaku/`）はツール本体の20コミットのうち15件が不具合の修正
だった。**実物のHTMLを見ていれば避けられたものが、確認できるだけで12件**。
残りは自分で入れた退行と、レビューで見つかった見落としが中心。以下はその再発防止。

---

## 着手チェックリスト

**実物を手に入れる（コードを書く前）**
- [ ] 開発環境から対象サイトへ接続できるか確認した。できないなら、以降は
      すべて推測になることを利用者に伝えた
- [ ] 対象が**地域・支店・年度ごとに別サイト**に分かれていないか確認した
      （前回は都道府県ごとに47サイト。実物で確認できたのは1県だけ）
- [ ] 一覧ページと詳細ページのHTMLを**実物で**入手した（下の依頼文を使う）
- [ ] 現行ツールがあるなら、その出力ファイルをもらった
- [ ] もらったHTMLを `tests/fixtures/` に保存した

**決めておく**
- [ ] 利用規約と robots.txt を見た。機械取得と再配布の可否を記録した
- [ ] **氏名などの個人名を出力に含めるか**決めた（迷うなら含めない）
- [ ] 出力に**出典サイト名・取得元URL・取得日時**を入れる設計にした

**作る**
- [ ] 抽出は画面の見出し語で引く。id/class に依存しない
- [ ] `<img alt>` を読む。**状態が画像で表されていることがある**
- [ ] 項目定義を外部ファイルに出し、文字コードは CP932 でも読めるようにした
      （利用者が Excel で開いて保存すると CP932 になる）
- [ ] 取得件数を、サイトが表示している総件数と突き合わせる
- [ ] 中断・再開用のデータは、完了時に破棄し、条件が変われば読み捨てる
- [ ] 出力ファイル名に、条件（都道府県など）を入れた。同日に2条件走らせても
      上書きされないこと

**渡す前**
- [ ] 初回起動（キャッシュ無し）・ブラウザ無し・通信失敗・出力ファイルを
      開いたまま、の4経路を試した
- [ ] 起動用スクリプトは、失敗したら画面を残す
- [ ] 少件数の**お試し実行**を用意した（本番と混ざらないよう名前を分ける）
- [ ] 利用者が**1ファイル送るだけで原因が分かる**診断出力を用意した。
      その出力には**見出しだけでなく値も**含める

## 利用者への依頼文（そのまま使う）

### まだツールが無い段階

> 対象ページのHTMLを1枚いただけますか。
>
> 1. ブラウザで対象のページを開く
> 2. `Ctrl + S` を押す
> 3. 「**Webページ、完全**」を選んで保存
> 4. できた `.html` ファイルを送ってください
>
> 一覧のページと、事業所1件の詳細ページ、それぞれ1枚ずつあると助かります。
> （画面のスクリーンショットでは構造が分からないため、HTMLが必要です）

### ツールがある段階

> `診断する.bat` をダブルクリックしてください。
> データの取得はせず、1分ほどで終わります。
>
> 終わると同じフォルダに `詳細ページ.html` ができます。それを送ってください。
> うまくいかない場合は、黒い画面に出ている文字をそのまま送ってください。

**依頼は1回にまとめる。** 前回はHTML・ログ・出力を別々に頼み、往復が増えた。

## 手順

### 1. 実物のHTMLを読む（コードを書く前）

推測で書くと、前回はこれだけ外した。すべて実物のHTMLで確認した事実。

| 推測 | 実際 |
|---|---|
| 市区町村→サービスの順 | **サービス→市区町村**（逆だと選択欄が存在しない） |
| 詳細ページは1枚 | **2枚**（概要と詳細で別リンク） |
| 詳細タブはリンク | **ボタン**。表示文字も無い場合がある（URLで辿る） |
| 一覧のリンク文字＝事業所名 | 「情報を選択して概要を見る」＝操作案内 |
| 事業所名は詳細ページの「事業所の名称」 | そこは**フリガナ**。名称は一覧側にある |
| あり／なしは文字 | **画像**（`<img alt="あり">`）。詳細ページの38項目が空欄だった |
| 加算は見出し→隣のセル | 2列の表で、隣は「(その内容)」＝事業所のPR文 |
| 住所には市区町村名がある | 無い行がある（`〒662-0916 津門稲荷町5-13`） |
| 休みの営業時間は空欄 | `0：00～0：00` と書かれている |

### 2. 抽出を作る（ブラウザ不要）

実物のHTMLに対してテストを書く。見出し語で引き、項目定義は外部ファイルへ。
見出しは NFKC 正規化して照合する（全角/半角・空白・括弧のゆれを吸収）。
**定義ファイルには正規化後の形で書く**（ローマ数字は `Ⅱ` ではなく `II`）。

→ 仕組みの詳細: `kaigo_kensaku/README.md`「サイトの構成が変わったとき」

### 3. 巡回を作る（模擬サイト）

模擬サイトに**実物の癖**を入れる。素直なHTMLで作ると、テストは全部通るのに
実サイトで1件も取れない、という状態になる（前回そうなった）。

→ 12パターンの実装: `kaigo_kensaku/tests/mocksite.py`
（うち実物由来は checkbox / link / select / textbox / textonly / imgtab /
iframe / pdftrap / real。deep・deadnext・js は「そうであっても壊れない」
ための備えで、実物で確認したものではない）

**修正を入れる前のコードで、そのテストが失敗することを確認する。**
テストを先に書き、赤いことを見てから直す。赤くならないテストは意味がない。
前回これを飛ばして次を出した。

- 模擬サイトが素直すぎて、テストは全部通るのに実サイトで1件も取れなかった
- テストが常にキャッシュを用意していたため、**初回起動の経路だけ検証されず**、
  利用者全員が通る道で画面が開かなかった

### 4. 運用に耐えさせる

→ 詳細: `kaigo_kensaku/README.md`「進捗ファイルの扱い」「取りこぼしの検知」

未検証の地域で動かすときは、最初の1件で診断を出して止める。
全件走り切ってから「空欄です」と言われても、数十分が無駄になる。

### 5. 渡す

`ツールを実行.bat` 相当は、失敗時に必ず画面を残す。
前回は `pause` が無く、利用者には「何も起きない」としか見えなかった。

## 判断に迷ったとき

**誤ったデータを出すくらいなら、空欄で出す。**
空欄は「取れなかった」と分かる。誤った値は正しい顔をして残る。

前回、あと一歩で「4区分すべて算定している」という制度上ありえない
データを出すところだった（確かめていない値を機械的に読み替えたため）。

- 値の意味が確認できていないうちは、読み替えをしない
- 「見出しは見つかったが値が使えなかった」を別に記録する。
  見つかったかどうかだけ見ると「取得できている」と誤判定する
- IDは数値にしない（先頭の0が落ちる）

**確かめていないことは、確かめていないと書く。**
前回、実サイトの検索フォームが JavaScript で組み立てられているかは
最後まで確認できなかった（開発環境から対象サイトへ届かなかったため）。
読み込み完了を待つ処理は入れてあるが、それは「そうであっても壊れない
ための備え」であって、不具合の原因として確認されたものではない。
コードのコメントや文書に「実際にこの不具合を出した」と書けるのは、
**再現できたときだけ**。

**実サイトで確かめられない性能改善は入れない。**
前回 `pageLoadStrategy=eager` を速度目的で入れたが、実測すると所要時間も
取得内容も変わらず、**指定自体が効いていなかった**。それでいて、市区町村が
取れなくなったとき最初に疑う先になり、切り分けに時間を取られた
（真因は別で、画面版を足したときにブラウザ非表示を既定にしたことだった）。
速度は必ず実測で、**現実的な規模**で測る（5件で測って問題なしと判断し、
実際の50件表示では二乗で効いて7倍遅かった）。

**同じ処理を2箇所に書かない。**
前回4箇所で起きた。二重化すると、本番だけ直してテストは古いまま通り続ける。

- 詳細ページの取り込みが、本番とテストに二重化 → `extract.harvest_pages`
- 取得ループが、コマンドライン版と画面版に二重化 → `src/runner.py`
- URLの組み立て規約が、`navigator` と `extract` に二重定義 → 一本化
- 一覧1件から行を作る処理が、本番と2つのテストに三重化 → `runner.row_from_listing`

## 前回出した不具合（型ごと）

上の手順で拾えるのは「実物を見ていれば防げた」ものまで。
残りはここに挙げる型で出た。**渡す前に、この表を上から確認する。**

| 型 | 前回の症状 |
|---|---|
| 初回だけ通る道 | キャッシュ無しの起動で画面が開かない。テストは常にキャッシュを用意していた |
| 終了処理 | ウィンドウを閉じるとロックが残り、以後ツールが起動できない |
| 画面と別スレッド | ワーカースレッドから画面部品を読み `main thread is not in main loop` |
| 画面を閉じた後 | 閉じた後も `after` が走り、エラーが出る |
| ログが無い | 画面版がログを一切書いておらず、障害調査ができない |
| 出力名の衝突 | ファイル名に都道府県が無く、同日に2県取ると上書き |
| 警告の誤発 | 全件スキップ時に「要確認列＝全28列」が毎回出て、本当の警告が埋もれる |
| 進捗の残留 | 正常完了後も進捗が残り、翌月の実行で先月のデータが出る |
| 進捗の混線 | 都道府県も今回の選択も無視して「取得済み」と判断し、県をまたいで混入 |
| 打ち切り判定 | ページ送りの終了判定が誤り、3ページ目以降を取り逃がす |
| 表記のゆれ | 市区町村名に件数が付く（`西宮市 (123)`）。落としてから照合する |
| 選択UIの連動 | 「すべて選択」が絞り込みと連動し、画面外の選択が残る |
| 設定の無視 | サービスの初期選択が設定ファイルの指定を無視して全選択になる |
| 進捗表示 | 最後に `7/6` と出る。残り時間が開始直後から「まもなく完了」 |
| テストの環境依存 | Chrome が無い環境でテスト25件が赤。`import` の可否だけで判定していた |
| テストの書き方 | ファイル途中の `__main__` で、後続クラスが単体実行時に走らない |
| コミット衛生 | 実行時キャッシュが追跡対象に入り、コミットに混入 |

## 前回作った再利用できる部品

次に似たものを作るときは、文章を読むより `kaigo_kensaku/` から移植するほうが速い。

| 部品 | 場所 | 何をするもの |
|---|---|---|
| 項目定義の仕組み | `config/fields_*.csv` + `src/extract.py` | 見出し語で引く。コード修正なしで項目を追加・修正できる |
| 定義ファイルの読み込み | `src/config.open_text` | utf-8 / CP932 のどちらでも読む（Excelで保存されても起動できる） |
| 模擬サイト | `tests/mocksite.py` | 12パターンの構成を再現 |
| ブラウザ有無の判定 | `tests/test_navigator_mock.browser_available` | 実際に起動を試す。import の可否では判定にならない |
| 取りこぼし検知 | `extract.total_on_page` + `src/runner.py` | サイト表示件数と取得件数の突き合わせ |
| 進捗の破棄条件 | `src/state.py` | 古いデータが今日の日付で出るのを防ぐ |
| 診断機能 | `main.py --diagnose-detail` | 利用者に1ファイル送ってもらうための出力（見出しと値） |
