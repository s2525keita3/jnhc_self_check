# 介護事業所情報取得ツール（居宅介護支援 / 訪問看護）

厚生労働省「介護サービス情報公表システム」から事業所情報を取得し、Excelに出力します。
旧 `itakukaigokensaku` の後継として、**市区町村をまとめて指定できる**ようにしたものです。

## 旧ツールからの変更点

| | 旧ツール | 本ツール |
|---|---|---|
| 市区町村の指定 | 1つずつ選択して実行 | **複数まとめて指定**（`神戸市*` で全区、`ALL` で県内全域） |
| サービス種別 | 居宅介護支援のみ | **居宅介護支援＋訪問看護**（設定で追加可） |
| 出力 | 1市区町村＝1シート | **統合シート（全件）＋市区町村別シート**の両方（C案） |
| 中断時 | 最初からやり直し | **続きから再開**（`logs/progress.json`） |
| 項目定義 | parameters.csv | `config/fields_*.csv`（見出し語ベースで構造変更に強い） |
| 体裁 | 素のまま | オートフィルタ・枠固定・罫線、日付と営業時間を整形 |

## 使い方

1. `ツールを実行.bat` を **ダブルクリック**
2. 必要な部品の準備が自動で走ります（初回のみ数分）
3. 画面が開くので、**都道府県・サービス・市区町村を選んで「実行」**

画面でできること:

- 市区町村を**チェックで複数選択**（すべて選択／政令市の全区／絞り込み）
- サービスは居宅介護支援・訪問看護をチェックで選択
- 進捗バーと残り時間の目安、経過ログ
- 「停止」でいつでも中断（次回は続きから）
- 終わったら「Excelを開く」

設定ファイルを直接編集する必要はありません。

Python が入っていない場合は、`ツールを実行.bat` が配布サイトを開いて案内します。
インストール時に **「Add python.exe to PATH」に必ずチェック**を入れてください。

### お試し実行

画面の「お試し：各市区町村 ◯件まで」にチェックを入れると、1つの市区町村に
つき先頭◯件だけ取得して終わります。設定を変えたあと、ちゃんと取れているかを
数分で確かめるためのもの。

- 出力ファイル名に `_お試し` が付く（本番データと取り違えないため）
- 進捗（続きから取得）には記録しない。記録すると次の本番実行が
  「取得済み」と判断し、◯件だけのデータが出てしまう
- サイト表示件数との突き合わせも行わない（最初から絞っているため）

設定を変えるときは `設定を開く.bat` をダブルクリックするとメモ帳で開きます。

Google Chrome がインストールされていれば、ドライバは自動で用意されます。

## 使い方（コマンドから）

```
pip install -r requirements.txt
python main.py
```

### 2. 設定

`settings.ini` を編集します。

```ini
[search]
pref = 兵庫県
cities = 神戸市*, 西宮市, 尼崎市, 芦屋市
services = 居宅介護支援, 訪問看護
```

`cities` の書き方:

| 書き方 | 意味 |
|---|---|
| `西宮市, 尼崎市` | カンマ区切りで複数指定 |
| `神戸市*` | 前方一致。神戸市の全9区をまとめて取得 |
| `ALL` | 都道府県内の全市区町村 |
| `@cities.txt` | テキストファイルで指定（1行1自治体） |

### 3. 実行

```
python main.py
```

`.exe` の場合はダブルクリック。`settings.ini` の `pref` / `cities` が空なら対話で聞きます。

```
python main.py --pref 兵庫県 --cities "神戸市*" --services "訪問看護"
python main.py --list-cities        対象都道府県の市区町村名を一覧表示
python main.py --restart            前回の進捗を捨てて最初から取得
```

実行中に出力先のExcelを開いていると保存できないため、閉じておいてください
（開いていた場合は `_1.xlsx` として保存します）。

## 出力

`介護事業所一覧_YYYYMMDD.xlsx`

- `居宅_全件` / `訪看_全件` … サービスごとの統合シート（先頭に「市区町村」列）
- `居宅_西宮市` `訪看_神戸市中央区` … 市区町村別シート
- `実行サマリ` … 取得条件・件数・失敗した検索・要確認の列

ヘッダーは旧ツールと同じ3段構成（1行目:大見出し／2行目:中見出し／3行目:項目名、4行目からデータ）です。

## 実サイトの導線

```
都道府県トップ → 介護事業所を検索する → 詳しい条件で探す
  → サービスの選択 → 事業所の所在地選択 → 検索
```

サービスを選ぶまで所在地の選択肢が現れないため、ツールもこの順序で操作する。
異なる作りのサイトでも動くよう、この順序で駄目なら市区町村を選べる画面を
探しに行くようにしてある（`Navigator._explore`）。

## 実サイトのページ構成（実物のHTMLで確認済み）

検索結果ページ（1件ぶん）に、次の情報がすでに載っている。詳細ページを
開かなくても取得できるため、まずここから読み取る。

- 事業所名 / 事業所番号 / 電話番号 / 公表日
- 所在地（〒と住所。住所に市区町村名が無いことがある）
- サービス提供地域 / 営業時間（平日・土曜日・日曜日・祝日）/ 定休日

さらに1件につき詳細ページへのリンクが**2つ**ある。両方開く必要がある。

| リンク文字 | URL | 内容 |
|---|---|---|
| 情報を選択して概要を見る | `action_kouhyou_detail_overview_index` | 種類・所在地・連絡先 |
| 詳細情報を見る | `action_kouhyou_detail_023_kani` | 従業者・利用者・加算など |

表示件数は `p_count` で 5/10/30/50 件を選べる（既定5件）。最大にして
ページ送りの回数を減らしている（西宮市127件なら26ページ→3ページ）。

`tests/fixtures/real_result_list.html` は実際の検索結果から2件を抜き出した
もので、`tests/test_real_html.py` がこれに対して読み取りを検証している。

## 実データで確認できたサイトの癖

| 癖 | 対応 |
|---|---|
| 一覧のリンク文字が「情報を選択して概要を見る」で事業所名ではない | 事業所名は詳細ページの見出しから取る |
| 詳細タブの作りが不明（リンク／ボタン／画像） | 同じ事業所番号を含む `action_kouhyou_detail_*` のURLを全部開く。無ければ表示文字をクリックする |
| 住所に市区町村名が無いことがある（例:「〒662-0916 津門稲荷町5-13」） | 検索した市区町村名と都道府県名を補う |
| 一覧が1ページ5件 | 表示件数を50件に変更してから、ページ送りで最後まで取得 |
| 営業時間の「なし」が「－」「0：00～0：00」「0：～0：」 | すべて空欄にする |
| 詳細ページの「事業所の名称」がフリガナ（けあらぼ） | 検索結果ページの名称（ケアラボ）を優先する |
| 事業所名が badge の「居宅介護支援」と紛らわしい | サービス種別名と完全一致する見出しは名称として採用しない |

## 進捗ファイル（logs/progress.json）の扱い

これは**中断したときに続きから取得するための一時データ**であり、前回の
結果を使い回すためのものではない。次の場合は読まずに捨てる。

- 正常に完了した（完了時に破棄する）
- 都道府県が前回と違う
- 前回の取得から36時間以上経っている
- `DATA_VERSION` が違う（取得ロジックを変えた）

ここを緩めると「翌月に実行したら先月のデータがその日の日付で出る」「別の
県の行が混ざる」という、**利用者が気づけない誤り**が起きる。

## 取得ロジックを変えたとき

`src/state.py` の `DATA_VERSION` を上げること。古い進捗ファイル
（`logs/progress.json`）を読み捨てるようになり、以前の取り方で集めた
データが再開時に混ざらない。

## サイトの構成が変わったとき

このツールは **画面に表示されている見出し語** で値を探します
（`id` や `class` に依存しないので、デザイン変更では壊れません）。

見出し語そのものが変わった場合は、`config/fields_*.csv` の `lookup` 列に
候補を `|` 区切りで足すだけで対応できます。コードの修正は不要です。

```csv
column,lookup,transform,group1,group2
所在地,kv:所在地|kv:事業所の所在地|kv:事業所所在地,addr,,
```

`lookup` の書き方:

| 記法 | 意味 |
|---|---|
| `kv:所在地` | 「所在地」という見出しの隣のセルの値 |
| `matrix:看護師/常勤` | 行見出し「看護師」×列見出し「常勤」のセルの値（行・列は逆でも可） |
| `ctx:city` | 検索条件など、ツール側が持っている値 |
| `re:特定事業所加算\(?II\)?$` | 見出し語を正規表現で探す（見出しのゆれ対策）。照合は NFKC 正規化後の見出しに対して行うため、ローマ数字は I / II / III と書く |
| `inval:^特定事業所加算$/II` | 「特定事業所加算 → Ⅱ」のように値の側に区分が書かれている形。値に含まれれば あり、無ければ なし |

`transform` は `text` / `int` / `date` / `time` / `addr` / `yesno` / `space` / `trim`。

うまく取れない列があるときは `settings.ini` で `dump_html = True` にして実行すると、
`logs/html/` に実際のHTMLが保存されます。

## 市区町村が見つからないと言われる場合

サイトの検索画面の作りが想定と違っています。`診断する.bat` をダブルクリックすると、
画面上のリンク・プルダウン・チェックボックスの一覧を `logs\診断結果.txt` に書き出します。
その内容をもとに `src/navigator.py` の `NAV` と選択処理を合わせ込めます。

市区町村の選択は、チェックボックス・プルダウン・文字入力・リンクの4通りに自動対応しています。
また、トップページから検索画面へ1クリックで行けない場合も、それらしいリンクを
2階層までたどって市区町村を選べる画面を探します。

## 項目が全部空になる場合

実行後に「※ ほぼ全件が空欄の列があります」と表示されたら、その列の見出し語が
想定と違っている。このとき、サイト上で実際に見つかった見出し語が
2か所に書き出されるので、それを見て `config/fields_*.csv` の `lookup` を直す。

- 出力Excelの「実行サマリ」シートの「見つかった見出し（サービス名）」
- `logs/見つかった見出し.txt`

出力Excelだけで原因が分かるようにしてある。

## テスト

```
python -m unittest discover -s tests -v
```

インターネットに接続せずにテストが走ります。Chrome が無い環境では、
ブラウザを使うテストは自動でスキップされます（実際に headless Chrome を
1回起動してみて判定する）。内訳:

- 抽出ロジックとExcel出力の検証（ブラウザ不要）
- 実サイトのHTML（`tests/fixtures/real_result_list.html`）に対する検証
- 画面版を実際に起動し、実行から出力までを通す検証（tkinter が無ければスキップ）
- `tests/mocksite.py` が立てる模擬サイトに対して、実際のChromeで
  検索 → 一覧のページ送り → 詳細タブ巡回 → 抽出 → Excel出力 までを通す検証

模擬サイトは市区町村の選ばせ方が異なる6パターンを再現しています。
実サイトがどの作りでも動くようにするためのものです。

| パターン | 内容 |
|---|---|
| checkbox | チェックボックスで市区町村とサービスを選ぶ |
| link | 市区町村はリンク、次の画面でサービスを選ぶ |
| select | プルダウンで選ぶ |
| textbox | 市区町村を文字で入力する |
| textonly | 市区町村は文字入力のみ、サービスを選ぶ部品が無い |
| deep | トップから2階層たどらないと市区町村に届かない |
| deadnext | 「次へ」を押しても同じページに戻る（無限ループ対策） |
| iframe | 検索フォームが iframe の中にある |
| pdftrap | PDFや案内ページの紛らわしいリンクが並ぶ |
| imgtab | 詳細タブが画像リンクで表示文字が無い |
| real | 実サイトの導線と癖を再現（サービス選択 → 所在地選択、ボタン式タブ、一覧のリンク文字が「情報を選択して概要を見る」、市区町村名の無い住所） |

Chrome/chromedriver が無い環境では、ブラウザを使うテストは自動でスキップされます。

## ブラウザの表示について

`settings.ini` の `display` は既定で `True`（ブラウザを表示する）。

ブラウザ非表示（headless）だと、実サイトで市区町村が1件も取れない事象が
起きた。非表示と分かる名乗り（HeadlessChrome）を避ける指定を入れたうえで、
非表示で取れなかった場合はブラウザを表示して自動で取り直し、成功したら
`display = True` を書き戻すようにしている。利用者に設定を触らせないため。

なお `pageLoadStrategy = eager`（JavaScriptの完了を待たずに進む設定）は
速度目的で入れたが、実測すると効果が無かったため取りやめた。画像の
読み込み停止も、実サイトで検証できないまま入れる危険のほうが大きいため
取りやめている。**実サイトで確かめられない性能改善は入れないこと。**

## 介護報酬の加算の取り方

実サイトの加算は、**行が加算名、列が「(前年同月の提供実績)」と「(その内容)」**
という表になっている。「その内容」には事業所のPR文が入るため、そちらを
拾うと、あり／なしの列に長文が入る（実際にこの不具合を出した）。

```csv
（Ⅱ）,matrix:特定事業所加算（Ⅱ）/（前年同月の提供実績）|...,yesno,...
```

**あり／なしは画像で表示されている。**

```html
<th>特定事業所加算（Ⅰ）</th>
<td><img alt="あり" src="/img/pref/ico_jigyosho_ari.gif"></td>
```

文字を拾うだけでは空になるため、`cell_text` で `<img>` の `alt` も
文字として読んでいる。この1点で、加算のほか損害賠償保険の加入、
従業者の健康診断の実施状況、介護予防支援の指定など**38項目**が
読めるようになった。画像で状態を表す箇所は他にもあるので、
新しい項目を追加するときはまず `alt` を疑うこと。

なお「(前年同月の提供実績)」に入っているのは `10人` という利用者数で、
あり／なしではない。**確かめていない値をあり／なしに読み替えないこと。**
空欄は「取れなかった」と分かるが、誤った値は正しい顔をして残る。

## あり／なしの列について

`transform` が `yesno` の列は、あり／なし相当の短い値だけを採用し、
解釈できない値は空欄にする。見出しの探索を緩くしている都合で、
無関係な文章（事業所のPR文など）を拾うことがあり、それをそのまま
出すと空欄よりも悪い誤りになるため。

`logs/見つかった見出し_<サービス名>.txt` に、サイト上で実際に見つかった
見出しを毎回書き出している。値が取れているように見えて別の項目を
拾っている場合は要確認列に出ないので、突き合わせる材料として残す。

## 取りこぼしの検知

検索結果ページが表示している総件数（「127件」）を読み、取得件数と
突き合わせている。一致しなければ実行サマリに記録し、画面にも
「【要確認】50/127件」と出す。ページ送りが途中で止まっても気づけるようにするため。

## 画面版について

- 画面は `gui.py`、取得処理は `src/runner.py`。コマンドライン版（`main.py`）と
  同じ処理を使っているので、直すのは1か所で済む
- 取得は別スレッドで動かし、画面へは `queue` 経由で渡している。
  **別スレッドから画面部品を触るとTkが落ちる**ので、必要な値は引数で渡すこと
- 取得スレッドは daemon なので、ウィンドウを閉じるときは停止を指示して
  `join` してから閉じること。そうしないとロック解放が走らず、ロックファイルが残る
  （残っても PID の生存確認で自動復旧するが、Chrome も残るため）
- 1件ぶんの行を作る手順は `runner.row_from_listing` に集約し、テストからも
  同じ関数を呼ぶこと。ここが二重化すると、本番だけ直してテストが古い手順の
  まま通り続ける
- 市区町村の一覧は `config/cities_cache/<都道府県コード>.json` に保存し、
  2回目以降は即座に表示する（取り直しは「市区町村を取り直す」ボタン）
- **キャッシュの有無で通る道が変わる**。テストではキャッシュを用意する場合と
  しない場合の両方を試すこと。ここを試していなかったため、初めて使う人が
  必ず通る「キャッシュ無しの初回起動」で画面が出ない不具合を出した
- 市区町村が0件のとき、「読み込み中」と「取得失敗」は必ず区別して表示する。
  同じ文言にすると、失敗したのか固まっているのか利用者に分からない

## .exe を作る

```
pip install pyinstaller
build.bat
```

`dist/itakukaigokensaku.exe` が出来ます。`settings.ini` と `config` フォルダを
同じ場所に置いてください。

## 注意

- サイトへの負荷を避けるため、ページ遷移ごとに `settings.ini` の `wait`（既定1秒）だけ待機します。短くしすぎないでください。
- セキュリティソフトで `.exe` がブロックされる場合は、作業フォルダを監視対象外に設定してください。
